Crypto Agent 架构说明
基于本地源码生成于 2026-06-18

一个长驻 daemon 驱动的加密交易 Agent

这个项目不是一个简单的命令行聊天机器人。当前实现是两进程架构： daemon 持有状态、策略、交易执行和 SQLite，CLI 只是通过 Unix socket 连接的薄客户端。

先纠正一个容易误读的点

心智模型

可以把 daemon 理解成交易控制平面。它持有账户相关状态、风险闸门、策略运行时、 心跳、cron 循环和持久化。客户端可以随时连接或断开，但不拥有交易状态。

两条执行路径

慢路径：LLM 循环加工具调用。快路径：市场数据触发策略信号，绕开 LLM 延迟。 两条路径最终都会落到共享的交易所抽象和风险控制原语上。

系统地图

关键边界不是“LLM vs tools”，而是“有状态 daemon vs 可替换客户端”。 所有可能影响资金的能力都放在 daemon 进程后面。

运行流程

使用标签切换几条主流程：聊天请求、自主执行、重启恢复，以及风险/下单串行化。

客户端发送聊天

IpcClient.startChat() 写入 JSONL chat 消息，包含 session、requestId 和内容。

daemon 持久化用户回合

handleChat() 解析会话，先保存用户消息，再调用 agent。

Agent 流式运行 LLM 循环

chatInSession() 做上下文压缩、注入世界快照，然后流式输出 OpenAI 或 Anthropic 响应。

工具按依赖执行

工具 handler 只拿到声明过的依赖：exchange、memory、config、soul、strategy store 等。

LLM 创建策略规则

plan_strategy、plan_ladder_strategy 或 plan_grid_strategy 写入带类型的策略快照。

daemon 实时启动策略

strategyAdded 启动单个策略，并让 executor 监听该 symbol，无需重启。

行情驱动策略

MarketFeed 监听 ticker、OHLCV 或 order book；能用 WebSocket 就用，否则轮询。

信号变成订单

OrderExecutor.handleSignal() 进入共享交易锁，评估风险，然后下单或拒绝。

systemd 启动 dist

用户级服务在项目目录运行 node dist/daemon.js，并读取 .env。

加锁并恢复状态

acquireDaemonLock() 防止重复启动；随后 daemon 恢复 soul、exchange、sessions 和策略状态。

对账交易状态

启动时恢复 active positions，并把 pending orders 与交易所 open orders 对账。

心跳、cron、快路径

心跳和 cron 循环启动；快路径要么监听活跃策略，要么报告 idle。

一个全局互斥锁

慢路径 buy/sell 工具和快路径 executor 在 daemon 进程内共享 tradeLock。

共享的风险判断

checkTradeAllowed() 是订单大小、回撤、敞口、日亏损、预算和余额检查的单一权威。

快路径 RiskGate

自动化信号使用 RiskGate，它委托同一个 trade guard，并更新 portfolio watermark。

下单与流水

成交订单会更新持仓、交易记录、daily PnL、pending orders，并广播 IPC 事件。

持久化状态

持久化设计遵循一条实用规则：只有当丢失状态会造成资金损失、审计缺口、 风险控制绕过或严重用户体验退化时，才应该持久化。

崩溃恢复状态
active_positions 保存本地 SL/TP 元数据。pending_orders 跟踪等待成交的订单。 daily_pnl 和 portfolio_watermark 避免风险限制在重启后被重置。
Agent 记忆状态
sessions, conversations, session_summaries, daemon_state, strategies 和 strategy_kb 保存用户上下文和策略研究结果。

运维流程

常规流程是先构建，再运行 daemon，然后连接 CLI。生产使用时，用户级 systemd 服务运行构建后的 daemon。

本地命令 
npm run build
	npm run daemon     # 前台运行 daemon
	npm run dev        # 连接 CLI 客户端
	npm test           # 运行 Vitest 测试
用户级服务 
npm run install:service
systemctl --user start crypto-agent
systemctl --user status crypto-agent
tail -f ~/.local/state/crypto-agent/daemon.err
当前可观测性注意点
Heartbeat 通过 HeartbeatScheduler 运行，但 "All clear" 结果不会持久化。 持久化设计文档明确把 heartbeat 最近运行元数据延后实现。如果需要可审计的 uptime 和健康检查， 应增加 daemon_state.last_heartbeat_at、last_heartbeat_result，或记录所有 heartbeat 结果。
