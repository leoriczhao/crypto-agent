Crypto Agent 项目全景说明

这个项目现在不是一个简单聊天机器人，而是一个长驻 daemon：它同时持有 LLM agent、LangGraph 工具循环、会话、 paper/live 交易执行、策略快路径、Resident Agent 调度、SQLite 审计和恢复状态。CLI 只是一个连到 daemon 的薄客户端。

4核心身份层：资金账户、交易账户、交易 bot、会话/agent

当前最重要的理解

交易层不是模拟 LLM。paper 模式只模拟执行和账户记账，行情仍来自真实公开市场数据。 LLM 可以通过工具创建 mandate、创建 resident trader、直接下单或创建策略；真正的资金隔离和审计落在 trading_bot、bot_allocations、agent_runs、paper_orders、 paper_fills 和 trades 上。

系统总图

当前代码的真实边界是：CLI 通过 Unix socket 把用户输入交给 daemon；daemon 内部同时运行 LangGraph agent、 Resident Agent scheduler、策略快路径和交易账户。所有状态都在 daemon 进程和 SQLite 中。

账户与 agent 映射

这是这次重构最关键的闭环。资金不是 session 的属性，也不是 LLM prompt 里的约定，而是落在 bot allocation 上。 Resident Trader 必须绑定 active strategy mandate 和 capital allocation 后才能运行。

为什么不是 sub-agent

旧的 sub-agents.ts 仍是一次性任务委派，例如 /research 触发 strategist loop。 新的 Resident Agent 是长期独立 actor，有自己的 session、schedule、bot、allocation、run history。 它不是主 Agent 的临时工具调用结果。

为什么不是 schedule 本身

schedule_expr 只表示“什么时候醒来”。策略依据来自 strategy_mandates， 资金边界来自 bot_allocations，风险边界来自 risk_policy 和统一风险门。

主 Agent 运行流

主 Agent 是用户面对的控制平面。它接收 CLI 消息、维护会话上下文、注入当前世界状态，并通过 LangGraph 循环调用模型和工具。

CLI 发起请求

src/cli.ts 渲染 Ink UI，IpcClient 通过 Unix socket 发送 chat、slash、status、cancel。

daemon 保存用户消息

CryptoDaemon.handleChat() 解析 session，先写 conversations，再调用 CryptoAgent.chatInSession()。

上下文压缩与当前状态注入

microCompact 压缩旧工具结果，autoCompact 可生成摘要；buildWorldSnapshot 查询资金、持仓、订单、策略，并由 injectEphemeralCurrentState 临时附加到本轮 user message。

LangGraph 执行循环

createAgentGraphRuntime() 编译一个两节点图：call_model 调 provider，若模型返回 tool call，则进入 tools，之后回到模型直到没有 tool call。

工具依赖注入

dispatchAgentTool() 根据 TOOL_DEPS 注入 memory、broker、market_data、sessionId 等，不在 agent loop 里为每个工具写分支。

结果流回 CLI

daemon 通过 IPC 发送 delta、tool_use、done；CLI 可取消请求，server 侧 abort provider stream。

Resident Agent 生命周期

Resident Agent 是这次重构后的长期自主 actor。主 Agent 可以用工具创建它，但创建出来以后，它由 daemon 的 scheduler 定期唤醒。

4. 构造运行 prompt

5. 创建 agent_run

6. 工具归因到交易

上线门禁现状

Trader runtime 现在要求 trader 必须有 active assigned mandate，但不强制 mandate 的 validation_status=validated。 原因是完整回测审批平台还没做。当前只是记录 deferred / pending / validated / rejected，后续 R1 平台再把它变成上线门禁。

交易层

交易层有一个清晰边界：观察行情和执行交易是分开的。paper 模式不需要交易 API key，因为执行本地模拟；live 模式才调用真实交易接口。

Paper 模式

CcxtMarketDataProvider 读取公开 ticker/OHLCV/orderbook； PaperBroker 负责订单、余额、仓位、保证金、PnL、fills。spot 和 USDT 线性合约都在 SQLite 内记账。

无需交易 API key 本地订单簿 mark-to-market 未模拟资金费率/强平

Live 模式

LiveExchange 是 CCXT wrapper。spot 直接下单；swap 会设置 leverage，传 marginMode、positionSide、 reduceOnly。CONTRACT_POSITION_MODE=auto 会检测 OKX one-way/hedge 并映射 posSide。

策略快路径

快路径是为了让策略按行情事件执行，不等 LLM 思考。LLM 负责创建策略，策略 runtime 负责订阅行情、发信号、过风险门、下单。

SignalStrategy

基于 Condition[] 的指标条件；与 backtest 共用 evaluator，减少回测/实盘逻辑偏差。

LadderStrategy

多价位分批进入，按加权均价统一 TP/SL。适合分层建仓。

GridStrategy

区间内挂 limit buy，并在成交后放 follow-up sell。更适合震荡行情，趋势行情风险较大。

SQLite 持久化

持久化原则：丢失会导致资金损失、审计缺口、风控绕过或严重 UX 回退的状态必须存。行情这种可重建外部数据不存。

不做旧库兼容

当前 schema 不再保留 llm_trader_jobs，也没有 ALTER TABLE 迁移兼容路径。 旧 SQLite 数据库需要删除或重建后再部署当前分支。这是刻意选择，不是遗漏。

风险、锁与恢复

风险不是只靠 prompt。慢路径工具和快路径策略都共享 checkTradeAllowed() 和全局 tradeLock。

统一风险门

trade-guard.ts 检查最大订单、仓位占比、总敞口、并发持仓、余额、drawdown 和 daily loss。 LLM 现货工具直接调用，快路径通过 RiskGate 调用。

全局交易锁

trade-lock.ts 串行化 risk-check + order-placement，避免两个会话或 LLM 与策略快路径同时改同一账户。

重启恢复

daemon 启动时恢复策略、active positions、pending orders；本地记录和交易所/纸面 broker 不一致时会标记 stale 或 orphan。

当前限制

paper 未模拟资金费率、强平和真实订单簿深度；Resident mandate 验证还不是强制上线门禁；live trading 仍需要人工确认配置和 key 权限。

后续边界

以下不是当前重构遗漏，而是明确延后或需要产品决策的内容。尤其不要把它们混进交易执行层。

R1: Mandate 回测审批平台

把 researcher 生成的 mandate 输入可重复回测、walk-forward、证据存档和审批流程。未来可以禁止未验证 mandate 分配给 unattended trader。

Resident Researcher

当前 runtime 支持 researcher role contract，但工具面主要先闭合 trader。研究员如何写入 mandate 草稿、如何通知主 Agent，还需要进一步产品化。

Live 多 bot 风险隔离

paper 已有 bot allocation。live 模式下多 bot 共享真实交易账户，必须进一步明确交易所子账户、仓位隔离或软预算 enforcement。

生产观测

当前有日志、事件和 DB 审计，但还没有完整指标、trace、alert、LLM token 成本和缓存率观测面板。
